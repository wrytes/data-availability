A storage network, explained

A file goes in. Strangers hold the pieces. Nobody knows who asked.

Eight short animations show how this project moves data: over UDP, through onion routes, past NAT routers.

1

Letters, not phone calls

Most of the internet works like a phone call. Both sides first agree to talk, and every sentence is confirmed. If one gets lost, everyone waits and says it again. That is TCP.

This network sends letters. A UDP packet carries its own address and goes out with no hello and no receipt. Some are lost. That is fine, because a file needs only half of its pieces, and anything missing is asked for again along a different route.

A file becomes shards

Four things happen before anything leaves your machine. The file is cut up, locked, padded with extra pieces and fingerprinted.

Storage nodes only ever see locked pieces of equal size. They cannot tell what the file is, how large it is, or which pieces belong together without the manifest you keep.

3

Who stores what

Every shard has a key, which is a hash. Every node has an ID. The two nodes whose IDs are closest to the key hold the shard.

Closest means XOR. Line the bits up and mark where they differ. The fewer differences, and the later they start, the closer the two are. Any node can work this out alone, so no one hands out assignments and there is no list to attack.

4

Half the network can vanish

Because any half of the pieces is enough, nodes can disappear without a trace. The file is lost only when fewer than half of the distinct shards are reachable anywhere.

A client can check without downloading. It asks for a few random shards and verifies each against the fingerprint. If more than half were missing, each check would fail about half of the time. Ten clean checks leave less than a one-in-a-thousand chance that the file is already gone.

5

Letters inside letters

Asking a node for a shard tells it who is asking and what for. So a request travels as an onion, wrapped in one layer for each of three nodes.

Each node removes its layer, learns only where to pass it next, and sends on a packet that looks completely different. Only the last node sees the request, and it never learns who sent it. The answer returns through a one-time reply block that the sender packed inside.

6

Meeting without addresses

Some nodes should not be reachable at all. A hidden node never opens a port. It only dials out, leaves reply blocks with three introduction points, and publishes a signed note saying where they are.

A client picks a meeting spot, the rendezvous point, then sends an encrypted knock through an introduction point. The hidden node answers at the meeting spot. Neither side learns the other's address, and the middle nodes cannot read anything.

Behind the router

A home router lets packets out and remembers where they went. Replies from that address are let back in. Anything else is dropped. That is why most devices cannot be reached from outside.

An attached node uses this. It talks only to three guards and sends a small keepalive every few seconds, so the router keeps its door open. Reply blocks name the node by a link id that the guard keeps, not by an address. If the router changes the port, the next keepalive updates the guard and delivery continues. No port forwarding, no reverse proxy.

8

The whole stack

Each layer only needs the one below it. The shards do not know about onions, and the onions do not know about shards.

The design borrows from Tor but is a different animal. It is a research prototype, not audited, and not as anonymous as Tor.

Filesmanifest + key

You keep the manifest. It lists the segment fingerprints and the key. Nobody else can read or locate the file.

Shardserasure code + Merkle

Locked, split, padded with extra pieces, fingerprinted. Any half rebuilds a segment. Repair regrows lost pieces.

Hidden holdersdescriptor, rendezvous

Storage nodes that no one can find or reach directly, only meet through a rendezvous point.

Onion packets2 relays + destination

Fixed-size layered packets and one-time reply blocks. Holders see a request, never the requester.

Linksguards, keepalive, link ids

Attached nodes dial out to three guards and stay reachable through them, even behind NAT.

UDPdatagrams, 1400 bytes

Letters with an address on them. No connection, no receipts. Loss is expected and tolerated.
